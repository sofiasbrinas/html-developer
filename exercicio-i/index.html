1. Evolução dos Computadores e da Web

(voltar ao topo)

Para entender a web moderna, é preciso olhar para a evolução do hardware e das redes. Os computadores passaram por diferentes gerações:

1 a Geração: Eram máquinas imensas. O Harvard Mark I (1944) era eletromecânico, seguido pelo Colossus (1946) , focado em criptoanálise na 2 a Guerra, e o ENIAC (1946) , criado para cálculos de balística. Curiosidade: o termo "bug" surgiu nessa época, pois insetos eram atraídos pelo calor das válvulas e quebravam as máquinas!
Evolução até os dias de hoje: A 2a geração trouxe os transistores (diminuindo o tamanho das máquinas), a terceira implementou circuitos integrados, e a 4 a foi marcada pelos PCs (Personal Computers). Hoje, vivemos a quinta geração, focada em IA, computação quântica e metaverso.

O Nascimento da Internet:

A comunicação em rede começou a ganhar forma na Guerra Fria. A semente foi plantada por teóricos como Joseph Licklider , que imaginava uma rede de comunicação global. Isso culminou na ARPANET , um sistema militar de comunicação em pacotes (com pontos de intersecção chamados de nós). A primeira conexão ocorreu em 1969.

Anos mais tarde, Tim Berners-Lee revolucionou esse cenário ao unir o hipertexto com os protocolos TCP/IP (criados por Vinton Cerf e Robert Kahn), dando origem à World Wide Web (WWW) e popularizando o HTTP e o HTML.

2. Entendendo a Arquitetura Client x Server

(voltar ao topo)

A internet que usamos para consumir páginas web e dados funciona em um modelo de requisição e resposta chamado Client-Server (Cliente e Servidor).

O Cliente (Client-Side): É o dispositivo ou navegador que você usa para acessar a internet. O cliente requisita informações ao servidor via protocolo HTTP. O navegador recebe os arquivos estáticos (HTML, CSS, JavaScript, imagens) e os transforma na interface visual. A velocidade da conexão e o sistema de cache do navegador (que evita baixar tudo novamente a cada clique) afetam diretamente a experiência. Além disso, no lado do cliente, a preocupação com o design responsivo é vital devido à variedade de dispositivos móveis.
O Servidor (Server-Side): É o computador responsável por hospedar, processar e distribuir os dados. Ele "serve" a página para o cliente.

Aplicações Web x Aplicativos:

Se você precisa instalar o software no seu dispositivo, é um aplicativo nativo. Se você acessa a solução através do navegador (como a Netflix no PC ou o YouTube web) e ela se comunica com um banco de dados nos bastidores, é uma Aplicação Web .

3. O Mundo dos Servidores (Servers)

(voltar ao topo)

Servidores não são apenas para a internet global; eles também operam em redes locais (LAN/Intranet). Por precisarem atender a muitas requisições simultâneas, possuem processadores e hardwares mais robustos.

Existem vários tipos de servidores com propósitos específicos:

  • Servidor Web: Focado em receber requisições HTTP e entregar sites.
  • Database (Banco de Dados): Dedicado ao armazenamento e consulta de dados estruturados.
  • Servidor Proxy e Firewall: Focados em segurança. O Proxy gerencia e bloqueia acessos (como controle interno de empresas), enquanto o Firewall protege contra ameaças externas.
  • DNS (Domain Name Service): Traduz os números de IPv6 (o "endereço" real do servidor) no nome de domínio do site (ex: google.com), facilitando a navegação.

Para subir um site para o ar, fazemos a Hospedagem , que é colocar os arquivos em um servidor web contratado. Muitas vezes usamos o protocolo FTP (File Transfer Protocol) , como o programa FileZilla, que cria uma conexão direta para enviar nossos arquivos locais para a nuvem.

4. Linguagens de Programação

(voltar ao topo)

Linguagens de programação são conjuntos de instruções formais usadas para criar softwares. A escolha da linguagem depende totalmente do escopo e ambiente do projeto.

Server-Side (Backend): São linguagens executadas no servidor, lidando com a lógica de negócios e banco de dados. Exemplos incluem PHP, Ruby, Java e C#.
Client-Side (Front-End): Executadas no navegador do usuário. O grande pilar aqui é o HTML JavaScript (JS) .

O JavaScript é tão versátil que hoje não vive apenas no navegador. Com a ajuda da Engine V8 e do ambiente Node.js, o JavaScript também pode ser rodado no lado do servidor, permitindo que uma mesma linguagem de programação atenda a todo o ecossistema do projeto.

5. HTML na Prática: A Estrutura da Web

(voltar ao topo)

Primeira regra vital: HTML não é linguagem de programação! HTML (Linguagem de Marcação de Hipertexto) é uma linguagem de marcação, assim como um arquivo CSV. Ele não tem lógica ou matemática, apenas usa "marcadores" (as tags) para dizer ao navegador o que cada parte do texto significa (se é um título, um parágrafo, um link, etc).

Para desenvolver, usamos IDEs como o Visual Studio Code , com a ajuda de extensões como o Emmet (que acelera a digitação) e o Live Server (que atualiza a página no navegador assim que salvamos o código). O Inspetor de Elementos (tecla F12 no navegador) é nossa principal ferramenta de suporte para ver como as tags estão sendo renderizadas.

A Estrutura Básica (index.html):

Um documento HTML é composto por três partes principais:

  • < html > ... : Envolve todo o documento.
  • < head > ... : A "cabeça" carrega configurações prévias, como links de CSS e a tag < title >, que define o nome que aparece na aba do navegador. O conteúdo daqui não aparece diretamente na tela.
  • < body > ... : O "corpo", onde vai tudo o que o usuário efetivamente vê e consome na tela.

Trabalhando com Tags e Atributos:

A maioria das tags precisa ser aberta e fechada (ex: < p >texto), mas algumas se fecham nelas mesmas (como < img /> ou < input type="text" />). Elas podem receber atributos para configurar seu comportamento, como:

  • id e class: Para identificar elementos e aplicar estilos (CSS).
  • src: Define a origem do arquivo (como o caminho de uma imagem).
  • style , type e width : Para definições visuais em linha, tipo de input e largura, respectivamente.

Tags Essenciais:

  • Textos: < h1 > a < h6 > para títulos em ordem decrescente de importância. < p > para parágrafos. < strong > para negrito, < i > para itálico, < u > para sublinhar e < blockquote > para blocos de citação.
  • Listas : Usamos < ol > para Listas Ordenadas (numeradas) e < ul > para Não Ordenadas (marcadores em ponto). Ambas recebem os itens da lista dentro de tags < li >.
  • Links : Criamos rotas de navegação usando a tag de ancoragem < a >. O atributo href recebe o destino do link. O atributo target define o comportamento: usar _blank abre o link em uma nova aba, enquanto _self (recomendado para links internos do próprio site) abre na mesma aba.

6. Conclusão e Próximos Passos

(voltar ao topo)

Compreender essa base teórica e prática é o alicerce de qualquer desenvolvedor. Passamos pelo hardware pesado da Primeira Geração de computadores, entendemos como a ARPANET moldou a comunicação mundial e como o ecossistema Client-Server faz a roda da internet girar hoje.

O HTML que você aprendeu a estruturar atua como o esqueleto de qualquer aplicação web, fornecendo semântica e organização aos dados. No entanto, a web moderna não vive apenas de estrutura bruta. Como sugerido nos próprios apontamentos, o próximo passo natural nesta jornada é estudar CSS. É com o CSS que você dará vida, estilo, cores e responsividade à marcação HTML que acabou de dominar, preparando o terreno para, futuramente, adicionar interatividade com o JavaScript!
